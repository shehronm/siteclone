# MIRO DIGITAL — изменения и проверка

Дата: 25–26 сентября 2026 года.

Доработан существующий проект из «Новая папка.zip». Сохранены страницы, секции, компоненты, медиа, локальные шрифты, исходная система анимаций и пути проекта. В архиве находился готовый HTML/React-экспорт с клиентскими чанками, а не исходники компонентов Next.js. Поэтому изменения внесены в имеющиеся HTML, CSS, API и соответствующие клиентские модули; новая версия сайта с нуля не создавалась.

**Что исправлено и почему**

| Область | Причина | Изменение |
|---|---|---|
| LET’S BUILD WHAT’S NEXT | Баннер наследовал отрицательный трекинг основного текста на очень крупном кегле | Нормализованы letter-spacing и kerning в существующем баннере. LET’S остаётся одним словом в одной чёрной плашке. LET’S / BUILD / WHAT’S — белые на чёрном; NEXT — чёрный на белом; стрелка mint. Кегль, порядок и анимация слов сохранены. |
| Уменьшение движения | WordOdometer оставлял visibility:hidden при prefers-reduced-motion | В этом режиме слова видимы без анимации. Обычный режим сохранён. |
| ДВИГАЕМ ВПЕРЁД. | Поздний CSS окрашивал второе слово в красный; смена темы могла дать белый фон под белым текстом | Оба слова белые, Ё сохранена. Чёрный фон соответствующей существующей панели закреплён в обеих темах. Размеры и композиция надписи сохранены. |
| DESIGN. BUILD. CONNECT. | Цвета слов были разными, затем пользователь уточнил единый чёрный | Все три слова теперь чёрные. Размеры, шрифт, расположение и анимация сохранены. |
| Стыки на скриншотах 1, 2 и 4 | В тёмной теме белая кнопка шапки сливалась с белым фоном под ней; серая карточка hero сливалась с нижним серым полем; тёмная карточка отзыва сливалась с активной тёмной строкой проекта | Добавлены три тонкие контрастные линии в самих существующих поверхностях. Использованы внутренние тени без изменения размеров и сетки. |
| Проекты | Поздний CSS задавал синий цвет; неполная локализация возвращала Selected work | Русский заголовок стабильно отображает «Проекты» чёрным. В тёмной теме у заголовка светлая подложка для контраста. |
| Планшетный заголовок | На 768/834 px слово «Проекты» выходило за границу левой колонки | В существующем правиле 768–1023 px соотношение двух колонок секции проектов изменено с 45/55 на 50/50. Это необходимое локальное исключение: шрифт и кегль заголовка не уменьшались. |
| Команда | В модальных окнах было по одному короткому абзацу; данные bio дублировались | Для Shehron, Alina Volkova, Timur Safarov и Madina Yusufova добавлено по 5 оригинальных абзацев на русском и английском. Обновлены отображаемые абзацы и дублирующее поле bio. Тексты раскрывают практику, специализацию, подход, ценность и сильные стороны, без вымышленных наград, работодателей и лет стажа. |
| Фото команды | Галерея использует WebGL, а модальные окна — обычные изображения | Единый CSS grayscale(1) contrast(1.05) применён к canvas галереи, её image fallback и портретам модальных окон. Файлы фотографий и кропы не заменялись. |
| Типографика | Очень плотный трекинг body и labels; разные fallback для кириллицы | Используются уже приложенные Suisse Intl / Suisse Intl Mono с системными fallback. Уточнены интервалы labels и body, line-height подписей и длинных описаний, видимый keyboard focus. Новые шрифты не скачивались. |
| Палитра | Крупная синяя панель перетягивала внимание | Панель поддерживающего текста в desktop hero стала нейтральной серой. Акценты оставлены в словах и UI. |
| Русская версия | HTML, встроенные данные React и жёстко заданные подписи расходились | Устранены обнаруженные ошибки React hydration, смешанная подпись «дизайнer» и ошибочные WHAT’S внутри русского текста. |
| Contact form | Проверялся только HTTP status; HTML с кодом 200 мог давать ложный успех | Нужны JSON и ok:true. Добавлены клиентский таймаут, обработка ошибок, согласованная валидация, состояния отправки, блокировка повторной отправки того же брифа, локализованные поля, сохранение данных и запасная ссылка на Telegram. |
| API | Не было явного подтверждения доставки; malformed JSON может выбросить исключение в Vercel | Нормализация и серверная проверка данных, явный JSON-контракт, корректные 400/405/415/502/503, обработка невалидного JSON и таймаута провайдера. Секреты остаются только в environment. |

Новые правила overflow:hidden для маскировки проблем не добавлялись. Существующие overflow для анимаций и внутренних скроллеров сохранены. Число !important в miro.css уменьшилось с 213 до 205; новый слой из десятков !important не добавлялся.

**Фактически выполненные проверки**

Среда: Windows, локальный HTTP-сервер, Microsoft Edge / Chromium через Playwright, Node.js 24.19.0. Телефонные сценарии проверялись через размеры viewport и эмуляцию touch; физические телефоны не использовались.

Ширины: **320, 375, 390, 430, 768, 834, 1024, 1180, 1280, 1366, 1440, 1600, 1920 px**.

- EN и RU, light и dark, все 13 ширин: 52 сочетания. Измерены границы страниц/секций и заголовка «Проекты», проверены цвета заголовка и двух слов hero. Переполнение не обнаружено после завершения адаптации анимаций к новой ширине. На финальных загрузках нет pageerror и ответов 4xx/5xx для ресурсов сайта.
- EN и RU, все 13 ширин: 26 сценариев открытия/закрытия contact modal, размеров внутренних контейнеров, обязательных полей и реального локального ответа API 503 без настроек. Проверены error state, сохранение введённых данных и удержание Tab внутри диалога.
- На ширинах с мобильным меню проверены tap, открытие и закрытие Escape. В обеих языковых версиях проверен переход из меню к команде и закрытие меню после перехода.
- В обеих языковых версиях открыты все 4 карточки команды: 5 абзацев bio плюс строка роли, доступность конца текста при прокрутке, grayscale и закрытие Escape.
- В обеих языковых версиях открыты и закрыты все 6 модальных окон проектов.
- Проверены desktop hover mint-стрелки и видимость всех четырёх слов баннера при prefers-reduced-motion.
- Локальный путь браузер → API → заглушка Telegram проверен для EN и RU: подтверждённая отправка, отказ Telegram и таймаут; повторная отправка того же брифа блокируется. HTML 200 и JSON без ok:true не дают успех. Пробельное имя отклоняется.
- Синтаксис всех 58 JavaScript/CJS-файлов проверен через `node --check`.
- `npm test`: **10 серверных тестов прошли**. Включены методы, content-type, формы body, невалидный JSON, типы/длины/значения полей, honeypot, отсутствующие настройки, успех, ошибки и таймаут провайдера. Внешние сообщения эти тесты не отправляют.
- FORMA, EMBER и LINE, EN/RU, все 13 ширин: 78 проверок размеров. Горизонтального переполнения и ошибок JavaScript не обнаружено. Дополнительно открыты/закрыты модальные окна FORMA и EMBER. Эти страницы остаются демонстрациями; настоящие заявки, бронирования и оплаты в них не подключались.
- Визуально просмотрены выбранные desktop, tablet и mobile скриншоты, включая баннер, команду, форму, hero и контраст в тёмной теме. Это не утверждение о ручном просмотре каждого пикселя на всех возможных устройствах.
- После изменений от 26 сентября повторно проверены EN/RU, light/dark и все 13 указанных ширин: ещё 52 сочетания. Измерены три чёрных слова, стили трёх линий, отсутствие горизонтального переполнения и ошибок страницы. Отдельно проверен desktop hover на Telegram Services и визуально просмотрены новые снимки стыков в обеих темах. Эти снимки сделаны в Microsoft Edge; Safari и реальные телефоны по-прежнему не проверялись.

**Что остаётся перед production**

По вашему уточнению сохранён Telegram. Настоящего токена и chat ID в архиве нет. Реальные Telegram-уведомления не отправлялись, получение в вашем чате и production-деплой не проверялись. Автоматическая отправка email не реализована и не заявляется: email посетителя включается в Telegram-заявку, а mailto остаётся запасным способом связи.

Добавьте TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID на сервере, разверните проект и выполните одну реальную отправку с проверкой сообщения в нужном чате. Настройте ограничение частоты запросов на хостинге перед значительным публичным трафиком. Подробности — в CONTACT-SETUP.md. До этих действий реальную production-доставку нельзя считать подтверждённой.

Safari, Firefox, реальные iOS/Android, нагрузочная устойчивость и полная сертификация доступности не проверялись. Код существующих анимаций и визуальные бренды вложенных демонстраций сохранены.
