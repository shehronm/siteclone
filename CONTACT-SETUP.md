# MIRO DIGITAL — заявки через Telegram

Проект подготовлен для размещения на Vercel. Серверный обработчик `api/contact.js` отправляет заявки боту в Telegram. Токен и ID чата остаются только на сервере. Развёртывание и доставка в настоящий чат в рамках этой проверки не выполнялись.

В настройках проекта используйте Framework Preset **Other**, корень этой папки, Node.js **24.x**, без команды сборки. Это существующий статический экспорт с Node.js API, а не исходный Next.js-проект для `next build`. Файлы `index.html`, `ru/`, `next-assets/`, `assets/` и `api/` должны попасть в один деплой. На хостинге, который отдаёт только статические файлы, обработчик работать не будет.

1. Создайте бота в Telegram через @BotFather и сохраните выданный токен у себя, не в исходниках.
2. Откройте бота и отправьте ему `/start`. Чтобы узнать ID личного чата, откройте `https://api.telegram.org/bot<ваш_токен>/getUpdates` **только у себя** и возьмите число `message.chat.id`. Для группы добавьте бота в группу, напишите в неё сообщение и возьмите ID группы из того же ответа.
3. В панели проекта Vercel → Settings → Environment Variables добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` для Production (и Preview, если тестируете preview-деплой). После этого сделайте новый деплой.
4. Откройте опубликованный сайт, отправьте пробную заявку через «Start a project» / «Обсудить проект». Успех в интерфейсе показывается лишь после подтверждения от Telegram API. Убедитесь, что заявка появилась именно в вашем чате. При ошибке форма сохраняет введённые данные и предлагает повторить попытку.

`mailto:` и ссылка на @sehron остаются запасными способами связи. При отсутствии серверных переменных обработчик отвечает 503 и форма не показывает ложное подтверждение.

Автоматической отправки email в проекте нет: выбранный канал уведомления — Telegram. Адрес посетителя включается в уведомление для последующего ответа команды. `mailto:` открывает почтовую программу посетителя.

Форма проверяет обязательные поля, длины и email; сервер дополнительно проверяет допустимую тему и пробельные значения. Успех требует HTTP 2xx и JSON `ok: true` от нашего API после подтверждения Telegram. Ошибки провайдера, сети, таймауты, HTML вместо API и отсутствие настроек приводят к error state. Введённые данные сохраняются. После успеха повторная отправка того же брифа блокируется до редактирования полей. Это защита интерфейса, а не гарантия уникальности между устройствами или после перезагрузки.

Перед открытием формы для большого трафика настройте ограничение частоты запросов к `POST /api/contact` средствами хостинга. Honeypot уже есть, но отдельного распределённого rate limiter в этом статическом проекте нет.

Локальные тесты серверной функции: `npm test` (10 тестов, внешний Telegram подменяется заглушкой). Перед production обязательна одна реальная проверка после добавления переменных: отправьте тестовую заявку, проверьте ответ API, затем убедитесь, что уведомление действительно пришло в нужный чат. До этого production-доставка не подтверждена.

Документация: [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage), [Vercel Node.js runtime](https://vercel.com/docs/functions/runtimes/node-js).

Не помещайте токен в браузерный JavaScript, HTML, Git или переписку. Для локальной проверки серверной функции используйте `vercel dev` с собственными локальными переменными окружения; обычный статический сервер Python не запускает `/api/contact`.
